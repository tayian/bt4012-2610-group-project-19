# LightGBM baseline

Run `python run.py lightgbm` from the repo root after installing `requirements.txt` and
placing the course CSVs in `data/raw/`. This command rebuilds the current features_v0 through
the existing load, clean and feature steps. `python run.py all` also includes LightGBM.
For an existing current feature table, run `python -m src.models.trees` to fit without
rebuilding it. Both commands default to two CPU threads; use `--tree-jobs` with run.py or
`--n-jobs` with the module to change that.

## Evaluation and files

- `src.models.linear.load_training` validates the saved splits with `read_splits()` and
  selects training clients before passing data to the model. No split is regenerated by
  the model module and no held-out test client is fitted or scored.
- `src.eval.metrics.cv_evaluate` fits five fresh models on the saved training folds. It
  supplies the shared tie-aware budget metrics, Brier score and net-recovery metrics.
- Every fit calculates `scale_pos_weight = negatives / positives` from that fit's labels
  only. This also applies after augmentation in the adversarial study.
- `src.eval.oof.write_frames` writes `results/oof/M3_v0.parquet` with the existing five-column
  OOF schema and updates `results/tables/main_results.csv`. Rerunning replaces this run's
  row and preserves the other model rows. Outputs are written only after CV succeeds.
- Weighted classifier scores are used for ranking; this run does not establish probability
  calibration. Brier is reported by the shared evaluator, without claiming calibrated risk.

The model uses the LightGBM defaults of 100 trees, 31 leaves, learning rate 0.1 and
min_child_samples 20, with seed 4012. It has no tuning or early stopping in this baseline.
Numeric missing values use LightGBM's native handling. Categories are selected with the
helpers in `src/models/preprocess.py`; observed levels are learned separately in each
training fold. Unseen validation categories become missing. The model keeps one column per
input feature, which also preserves the order of adversarial monotone constraints.

## Shared tree interface

```python
from src.models.trees import PARAMS, fit_m3

model = fit_m3(X_train, y_train)
scores = model.predict_proba(X_valid)[:, 1]
```

`X` must be a pandas DataFrame of predictors only: no client_id, target or fold. The fitted
classifier stores its training category levels and reuses them at prediction time.
Optional LightGBM parameters can be passed as keyword arguments, for example
`fit_m3(X_train, y_train, monotone_constraints=constraints)`.

`PARAMS` contains the default LightGBM keyword arguments, excluding scale_pos_weight and
monotone_constraints. It is not a claim that tuning has been completed. Call `fit_m3` so
category handling and per-fit weighting are included. The compatibility module
`src.models.trees_standin` re-exports PARAMS and fit_m3 for existing imports.

`src/eval/adversarial.py` now imports the shared fitter for both its tree studies. Its
separate dependency on the attacked-invoice feature builder remains to be implemented.
`src/eval/rescue.py` already reads `results/oof/M3_v0.parquet` when called with `--m3 v0`,
so its input format needs no change. It also needs the anomaly-model OOF files.

No shared file format changes, so the stub generator needs no modification.
